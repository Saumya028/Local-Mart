# LocalMart — Steps 0–7: Foundations through Production Hardening

Step 0 proved the wiring. Step 1 added auth. Step 2 added browsing. Step
3 added cart & checkout. Step 4 added order history/tracking and
addresses. Step 5 added the Shop Dashboard. Step 6 added the Admin
Panel. Step 7 is the production hardening pass.

Per the roadmap's own framing, this phase isn't building new habits from
scratch — it's validating (and in several places, actually finishing)
habits earlier phases were supposed to already have. Two honest findings
from that validation, both real and both fixed:

- **There was no CI, and no tests, anywhere in this project until now.**
  Phase 0 asked for "Basic CI... runs lint + build on every push."
  Phases 1, 3, 5, and 6 each separately said "don't skip: write tests."
  None of it ever got built. This phase adds both — a real (if
  deliberately narrow) test suite, lint on both apps, and a GitHub
  Actions workflow that runs all of it on every push. See each folder's
  README for exactly what's covered and what honestly still isn't.
- **A dependency vulnerability scan found real CVEs, not hypothetical
  ones** — including a critical-severity one in the version of Next.js
  this project was built on. Both apps' dependencies were audited,
  patched where a safe patch existed, and the one exception (a
  Starlette CVE whose fix breaks compatibility with the pinned FastAPI
  version) is tracked and documented rather than silently ignored — see
  `backend/README.md`.

## What's new in Phase 7 — Production Hardening

**Security**
- Redis-backed rate limiting on checkout (10/min per user) and
  `/auth/me` (30/min per IP) — fails open if Redis itself is down, since
  rate limiting is a defense layer, not the thing guaranteeing
  correctness.
- CORS now accepts a comma-separated list of origins (staging + prod
  together) — still never a bare `"*"`.
- Security response headers on the frontend (`X-Content-Type-Options`,
  `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`).
- `pip-audit` and `npm audit` now run in CI on every push.

**Reliability**
- A runnable backup/restore verification script
  (`backend/scripts/backup_restore_check.sh`) — pg_dump your real
  database, restore it into a throwaway local Postgres, sanity-check the
  row counts. "A backup you've never restored isn't a backup," made into
  a five-minute check instead of a leap of faith.
- A catch-all exception handler on the backend, and `error.tsx` /
  `global-error.tsx` / `not-found.tsx` boundaries on the frontend — an
  unhandled error anywhere no longer leaks a raw traceback or blanks the
  whole page.

**Observability**
- Structured JSON logging with a request ID that's generated by the
  frontend, sent as `X-Request-ID`, echoed back by the backend, and
  attached to every log line either side emits while handling that
  request — the actual mechanism behind "trace one request across
  frontend -> backend."
- Optional Sentry integration on both apps — a true no-op with nothing
  installed-and-idle when no DSN is configured, fully wired up the
  moment one is.

**Performance**
- A real index audit (migration `0004`): missing foreign-key indexes,
  hot `WHERE`/`ORDER BY` columns that had none, and composite indexes
  replacing redundant single-column ones on the two busiest query
  patterns (order history, the Shop Dashboard's order list).

**Compliance**
- Privacy Policy and Terms of Service pages — explicitly labeled as
  working templates that need real legal review, not a launch-ready
  substitute for one.
- Payments are direct, customer -> shop (UPI or cash). LocalMart never
  holds or processes money, so there is no payment gateway, no webhook and
  no payment API keys. See "Direct payments" below.

## Direct payments (UPI / cash)
- Each shop sets a UPI ID and/or uploads its UPI QR, and turns "accept
  cash" on/off, under **Shop Dashboard -> Payments**.
- At checkout the customer picks UPI or cash **per shop**. For UPI the
  order page shows a "Pay with UPI app" button (opens GPay/PhonePe/Paytm
  with the amount filled in), a QR code, and an "I've paid" button with an
  optional UTR field.
- The platform can't see the transfer, so the **shop confirms** it
  ("Payment received" in Orders). Cash is marked paid automatically when
  the order is marked delivered / picked up.
- Orders start as `confirmed`; payment state is separate
  (`unpaid -> submitted -> paid`). Customers can cancel an unpaid order
  before the shop starts on it; shops can cancel before dispatch (stock is
  released).
- Exchange price differences are paid the same way and confirmed by the shop.
- Admin -> Settings -> Payment Gateway switches UPI / cash on or off for the
  whole platform.
- Run `alembic upgrade head` (migration `0016`) and `npm install` (adds
  `qrcode.react`).

1. `cd backend && pip install -r requirements-dev.txt && ruff check . && pytest tests/ -v` — should be clean (the integration tests need Postgres + Redis running and skip otherwise).
2. `cd frontend && npm install && npm run lint && npx tsc --noEmit && npm run build` — should be clean (a handful of known, tracked lint *warnings* are fine — see `frontend/README.md`; zero *errors*).
3. Push a commit (or open a PR) and confirm `.github/workflows/ci.yml` runs both jobs green.
4. Hit checkout 11 times in a row as the same user within a minute — the 11th should return `429`.
5. `curl -i http://localhost:8000/health | grep -i x-request-id` — confirm the header comes back.
6. Visit a nonexistent URL on the frontend — confirm the friendly 404, not a framework default.
7. Scroll to the bottom of any page — confirm the Privacy Policy / Terms of Service links work.

## Sponsored (paid-priority) shops

Shop owners buy promotion themselves: **Shop Dashboard -> Promote** -> pick a
plan -> pay. The moment the payment is verified the shop ranks above
non-sponsored shops (product search, `/stores`, landing page) until the plan's
days run out. Customers see no "Sponsored" label — it only changes the order
(and the public API doesn't expose it). Renewing early stacks days
on the current end date. Admins don't grant it: **Admin -> Manage Shops**
shows each shop's status (Active until / Expired / Not purchased), a
**Sponsorships** sub-tab lists who bought what and total revenue, and
**Admin -> Settings -> Shop Promotion Plans** edits plan prices. Admin can
"End promotion" for moderation only.

Search ranking: in-stock first, then sponsored shops, then name matches, then
nearest (when the customer shares their location, results are limited to
shops within the delivery radius) or best-rated.

Setup: `alembic upgrade head` (migrations 0018, 0019; seeds 3 placeholder plans:
Rs 199 / 599 / 1499 — change them in Settings). Payments:

- **Real money:** set `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` (and
  `RAZORPAY_WEBHOOK_SECRET`) in `backend/.env`. In the Razorpay dashboard add a
  webhook to `POST https://<your-api>/sponsorship/webhook` for the
  `payment.captured` event — it activates the plan even if the buyer closes the
  tab right after paying.
- **Local dev with no keys:** a clearly-labelled TEST mode activates plans
  without charging. It is automatically disabled when `ENVIRONMENT=production`.

## Promotional banners

Shops buy banner space on pre-decided spots (home top, home middle, search
top, stores top). Flow: **Shop Dashboard -> Banners** -> pick a spot, upload
artwork -> **Admin -> Banners** approves or rejects it (with a reason) -> the
owner pays (Razorpay, same keys as sponsorship) -> it runs for the spot's
duration (30 days by default) -> the owner renews from the same screen.
Approval comes before payment, so a rejected banner never needs a refund.

Locality: a banner is shown only to customers within **Banner Visibility
Radius** (Admin -> Settings, default 1 km) of the shop. The customer's browser
shares a location (after they tap "Share your location"), rounded to ~100 m;
the server does the distance check and does not store it. No location = no
banners. Clicking a banner opens that shop's page. Owners see views/clicks.

Setup: `alembic upgrade head` (migration 0020, seeds 4 placeholder spots at
Rs 1999 / 1299 / 999 / 799 — edit under Admin -> Settings -> Banner Spots).
The shop must have its map location (latitude/longitude) set, otherwise it
can't request banners. Check everything end to end with
`python backend/scripts/sponsorship_integration_check.py`.
